# Cold-read proof — 2026-08-16

A map that claims a cold reader can wander it should be made to prove it. This is that test,
including the part where the reader broke the rules and was right to.

---

## The test

A fresh agent session with no prior context — it had never seen Polis, the map, or the method
behind it — was given one path:

> `example-map/catalog.md`

and one task:

> **"Add a game event that suppresses one faction's food production for a few cycles."**
> Work out where that change goes and what else in the system it will disturb.

**Constraints:**

- Start at the catalog. Follow whatever it says.
- **Do not open anything under the Polis repo.** The point is to find out whether the map
  alone can direct you.
- **Do not open `identity.md`, `rules.md`, `README.md`, `examples.md`, or `reference/`** —
  those describe how the map was made, not the map. Only `example-map/` was in scope.
- **Log every file you open, in order.**

It was not told the one-card rule. The catalog had to convey that itself.

## What it answered

**Placement, on the first card.** The template belongs at position 17, the effect at
position 13. Correct.

**The load-bearing detail, which is not where you would assume.** "For a few cycles" cannot
be done by setting the flag and letting it ride — position 26 clears `faction.withholding`
on every faction, every pass. Duration has to live on the event as `cycles_remaining` so
position 13 re-sets the flag each pass.

**The blast radius**, traced in tick order: the one-pass arrival delay; 13 → 14 in the same
pass; 14 fanning out into six public scales; a same-pass feedback loop where 14's bands gate
17's need-gated templates; two independent paths to a game-over at 22 and 23; and a stacking
risk that exists for random events but not scripted ones.

**Seven wrong neighbours**, each named before it could be walked into. The best of them:

> **`EventEffect` with `field: "drift"`.** […] There is a real branch, the field exists, it
> clamps correctly, it serializes, it round-trips through the loader. And: "No engine code
> reads `domain.drift`."

On which the reader's own verdict:

> That is precisely the reach I'd have taken — an event effect that tilts a sector's output
> — and it fails with no error and no observable change. I'd have written it, tested it,
> seen nothing happen, and had no thread to pull. **The map caught it before I typed
> anything.**

## Where it broke the rule — and what changed because of it

The catalog then said: *"find your question below, open that ONE card, stop."* The reader
opened eleven files and said so plainly:

> The map did not tell me — I decided, and I deliberately broke the map's stated stop rule.

Its diagnosis, which was better than the complaint:

> I think the rule is written for a lookup question ("what does position 13 do?"), not a
> change-impact question ("what else moves?"). For the latter, the map's own `Hits` /
> `Does not hit` sections are explicit outbound edges […] Following those is clearly the
> intended traversal, but the catalog's front-door instruction doesn't say so.

It was right, and the gap was in the method, not the walk. **The stop rule has since been
split** — a lookup stops at one card; a change walk follows only the cards a card's `Hits`
names and stops when the edges close. The boundary that keeps that honest: *if you cannot
point at the card that sent you, you are browsing.*

This transcript was produced against the **pre-fix** catalog. It is kept as-is because the
defect it found is the reason the rule changed.

It also reported the honest ceiling of a single card:

> Card 13 alone would have gotten me to roughly 60% of the answer, and it would not have
> warned me about the `drift` ghost, the position-26 clear, or the ostracism disaster scan.

## What the map could not give it

Recorded because a proof run that only reports successes is not proof.

The map is precise about **positions and consequences** and vague about **authoring syntax**.
Everything unresolved was in the second category:

- The exact discriminator that makes an `EventEffect` set `withholding` — inferred from one
  line on one card, against a documented field list that does not include it.
- How an effect targets one specific faction. Every card says "its target" without naming
  the field.
- Whether suppression can be partial. Both cards say "zeroes"; if the flag is boolean, a 40%
  reduction is new engine work and a much larger task.
- **Where deck templates are actually declared.** For a task whose main deliverable is a new
  template, that is a real hole.
- Whether random events deduplicate — inferred from silence, not stated.

Its own confidence split: **high** on placement and blast radius, **medium** on the
mechanism. The first file it would open given the chance is
`backend/engine/events/event_system.py:355-380`.
